# Initial REST API Contract

All portal APIs are routed as `/api/v1`. Except OIDC discovery/login/callback, requests require a valid bearer token or approved BFF session. `201` denotes creation, `202` accepted asynchronous processing, `204` no content; errors are `400` validation, `401` unauthenticated, `403` unauthorized, `404` absent/not visible, `409` state/idempotency conflict, `422` business validation, `429` rate limit, and `5xx` server/dependency failure. Collection endpoints use `page`, `size`, `sort` and documented domain filters; responses are `{items, page:{number,size,total}}`. Exact field sets remain implementation contracts, not fake data.

|  | `POST /leave/requests`; `POST /leave/requests/{id}/cancel` | Create/cancel own leave; `leave.create.self` / `leave.cancel.self`; type/start/end/reason body; validate balance, date range and lifecycle. |
|  | `POST /leave/requests/{id}/decisions` | Direct permitted decision only where configured; `leave.approve.team/all`; decision/comment; validate workflow/task/state. |
| Payroll* | `GET /payroll/payslips/me`, `GET /payroll/payslips/{id}`, `GET /payroll/payslips/{id}/download` | **Implemented** (Phase 4) - self/authorized payslip list (period/financial-year filter, paginated), detail, and secure download reference; `payslip.read.self/all`, server-side ownership resolution; no real salary/tax calculation value - the pending pay-component catalogue/statutory rules (`docs/PAYROLL_REQUIREMENTS.md` Section X) are displayed as "not configured," never fabricated. |
|  | `GET /payroll/periods`, `POST /payroll/periods`, `GET /payroll/runs`, `POST /payroll/runs`, `POST /payroll/runs/{id}/{process,submit,approve,reject,finalize,adjustments}` | **Implemented** (Phases 1–4 plus Adjustment Runs): period/run lifecycle including a real calculation pipeline (`process` resolves effective compensation, applies configurable no-formula calculation/proration strategies, and produces `PayrollRunLine`/`PayrollException` results), the maker-checker approve/reject/finalize flow with self-approval prevention, and `POST /payroll/runs/{id}/adjustments` (creates an `ADJUSTMENT` run against a `FINALIZED` original via `corrects_run_id`, reusing the identical calculation/approval/finalization/payslip pipeline); `payroll.process`/`payroll.approve`/`payroll.read.all`; no real salary/tax calculation value, no pay-component catalogue content, and no adjustment/netting accounting policy - all remain PENDING_GDB_APPROVAL. |
|  | `POST/GET/PATCH /payroll/compensations[/{id}]`, `POST/GET/PATCH /payroll/pay-components[/{id}]`, `PUT/GET /payroll/statutory-profiles/{employeeRef}`, `GET /payroll/exceptions`, `POST /payroll/exceptions/{id}/resolve` | **Implemented** (Compensation Management revision, `docs/PAYROLL_REQUIREMENTS.md` Section G/E/O): HR/Finance CRUD for effective-dated `EmployeeCompensation` + components (with overlap prevention and historical-immutability-once-used-by-a-`FINALIZED`-run), `PayComponent` catalogue CRUD, per-employee PF/ESI/Professional-Tax statutory profile (applicability status never inferred from a missing identifier), and extended `PayrollException` list/resolve; all gated by `payroll.process`/`payroll.read.all` only - **no self-service endpoint exists for any of this data**, and no new permission was introduced (the HR-vs-Finance split remains PENDING_GDB_APPROVAL). No salary amount, catalogue content, or statutory rate/threshold is implemented. |

| Documents | `POST /documents/uploads`, `POST /documents/uploads/{id}/complete` | Start/complete own permitted upload; `document.upload.self`; metadata/scan completion only; validate type/size/checksum and quarantine state. |
|  | `GET /documents/{id}`, `GET /documents/{id}/download`, `GET /policies` | Authorized metadata/download/policies; `document.read.self/team/all`; access check, scan status, short-lived download result. |
|  | `POST /policies`, `PATCH /policies/{id}` | Publish/manage policy; `policy.publish`; document reference/status body. |
|  | `POST /documents/workload-uploads` | **Implemented.** Workload-identity upload on behalf of a named employee, for a service (initially Payroll's payslip generation, see `docs/PAYROLL_REQUIREMENTS.md` Section N/U) that must create a document for someone other than the caller; `workload.document.upload` — a distinct workload/client-credentials authority, never a `document.*` user permission and never held by a relayed employee token. Body carries an explicit `ownerRef` (the target employee), classification, MIME type, size, and checksum. Creates the document in `PENDING_SCAN`; the same authorized workload then completes it through the existing `POST /documents/uploads/{id}/complete` (also granted `workload.document.upload`), reusing the unchanged `PENDING_SCAN → AVAILABLE/QUARANTINED` checksum-match gate — no second upload or scan mechanism. Secure download needs no new endpoint: the existing `GET /documents/{id}/download` (`document.read.self/team/all`) already serves the owning employee once `ownerRef` is set. Idempotent per `(ownerRef, checksum)` — a duplicate submission is rejected `409`. Does not weaken `document.upload.self`/`document.read.self/team/all`. |

|  | `POST /workflows/{id}/tasks/{taskId}/decisions`, `POST /workflows/{id}/cancel` | Decision/cancel; `workflow.decide.assigned`; decision/comment; validate active assignment/delegation/terminal state. |
| Notifications | `GET /notifications`, `PATCH /notification-preferences/me` | Own messages/preferences; `notification.read.self`; pagination, channel/enabled body. |
| Audit | `GET /audit/events` | Restricted search; `audit.read`; filters actor/resource/action/time/correlation, paginated and redacted. |
| Reporting* | `GET /reports`, `POST /reports/{id}/runs` | Scoped report/run; `report.read.self/team/all`, `report.export`; filters/report parameters validated against approved definition. |

`*` endpoints are documented contracts only and remain unavailable until their deferred domains are approved. Service-to-service endpoints use separate internal routes/audiences and are not browser-public.
